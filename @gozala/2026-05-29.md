## Correspondence

> One quirk I noticed with effects is that they fire structurally, so if I have a set-status with `{target,status}` schema and delete-book with `{target}` and both `.targets` are declared on `dom.event.target.dataset/id`, a set-status could trigger delete-book if the effects are declared together.

Not sure I fully understand the issue, but I wonder if this is the thing I observed with todo list where click target isn't necessarily an element on which you have a listener. Specifically here is an example

```html
<ul>
  <li onclick=toggle-todo data-subject={this}>
    <wa-checkbox checked={done} />
    <span>{title}</span>
  </li>
</ul>
```

This required following command (transient) definition

```yaml
concept!:
  transient:
  with:
    todo:
      description: Subject todo to be toggled
      the: dom.event.current-target.dataset/subject
      as: entity
```

> [!note]
>
> Initially I wrongly used `dom.event.target.dataset/subject` instead which meant that click had to be precisely on the `<li/>` and clicks on the `<span/>` or `<we-checkbox/>` would not produce command because they had no `dataset.subject`

I suspect @jackddouglas is running into similar thing except, if you do have `data-id` on those elements you will end up getting command but on a wrong subject if those `data-id`s are different.

> [!warning]
>
> It is worth knowing that system does not actually sets listeners on the mom elements where `onclock` is present, instead listeners are installed on the [`shadowRoot`](https://developer.mozilla.org/en-US/docs/Web/API/ShadowRoot) and when event bubbles, handlers works out closest ancestor of event target with a matching handler and derives command from it.

This means if that if you have a template like the one in the example below clicking will produce `report-inner` command and not `report-outer`. Which may be an idea worth revisiting, but it seemed like a better choice than introducing ways to stop event propagation or producing multiple matches. 

```html
<div onclick=report-outer data-subject={this}>
  <div onclick=report-inner data-subject={header}>
    <span>click me</span>
  </div>
</div>
```

## Unique command entities

> ```yaml
> rule!:
>   assert!: book
>   when:
>     - assert: add-book
>       where: { this: ?this, title: ?title, ... }   # ?this == "dom:event"
> ```
>
> If an attribute is cardinality-one, the second add overwrites the first. So instead of adding two books, only the latter one survives: `{"this":"dom:event","title":"The Brothers Karamazov"}`.
>
> Possibly, if `this:` is excluded from transients, the entity's ID would be content-addressed instead.

I worked on this problem yesterday and should have PR up shortly. Changes remove `dom:event` and instead derive entity from command just like concepts do when you do `book!`.
