# Reloads got slower the longer the SW lived

Space loads were slow, and each reload made them slower (7.5s settling time climbing past 11s), resetting only when the service worker restarted. Profiled it in Chrome and the network was innocent: offline reloads were just as slow, so the cost lived inside the SW's wasm worker.

Two per-client structures accumulated without bound, because every reload assigns the page a fresh client id and nothing reconciled the old one. Each load stamps `site:<client-id>` facts into the branch overlay, and the GC the client-id keying was designed for was never implemented, so every read folded an ever-growing overlay. And a dead page's SSE subscription is only pruned when a send fails, which needs the response stream's receiver to actually drop; a vanished client may never trigger that, so its queries re-evaluated on every poll forever.

The fix ([#595](https://github.com/tonk-labs/tonk/pull/595)) reconciles both against `clients.matchAll()` in the existing per-fetch sweep: subscribers now carry the client id they serve, stamped sites are registered per client, and dead clients' state drops. Overlay removal needed a new primitive, `Overlay::retain_entities` in dialog ([dialog-db#390](https://github.com/dialog-db/dialog-db/pull/390), pinned via the `tonk-2026-07-12-2` tag): retracting would only grow the overlay with tombstones, and clearing would take unrelated sessions' facts with it. Reloads now settle flat at ~1s across 16+ consecutive rounds, and offline / Slow 3G reloads match online speed.

> [!caution]
> `clients.matchAll()` omits uncontrolled clients by default, and a document mid-navigation is uncontrolled. Sweeping against the default set would treat a page that registered state moments ago as dead. The sweep queries with `includeUncontrolled: true`.

## The inspector that would not leave

Same-document navigation between `/space/{id}` and `/space/{id}/inspector` left the nested site on the old sub-path, in both directions. Two separate defects, one per direction.

Forward: `<tonk-site>`'s `attribute_changed_callback` treated any change whose old value was empty as a first-set and skipped re-routing. But an absent `path` is a routed state (`/`), so the empty-to-value transition is exactly the bare-route-to-sub-path navigation. `path` changes now always re-route; the same-route iframe reuse makes that just a `tonk:load` re-claim, no teardown.

Back: the bare `/space/{id}` route captures no `{rest}`, and `stamp_site_on` merged into the site's existing overlay facts, so the stale cardinality-one `rest="inspector"` survived and the chrome re-rendered `path={rest}` with the old value. A re-stamp now replaces the site entity's facts, using the same `retain_entities` primitive the sweep needed. Both directions verified live: forward mounts the inspector, back restores the space view, no reloads.
