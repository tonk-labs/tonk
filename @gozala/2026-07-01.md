# July 1st

## FAB names that would not stay in their box

Renaming a space to something long broke the FAB in three ways in a row, and each fix exposed the next. First the name spilled past its segment and painted over the sync circle. The `.fab__space` editable had a fixed `max-width` with an ellipsis, but a `:focus-within` rule lifted the clamp while editing, so a long name rendered outside its box. Dropped the lift and let the segment shrink-wrap up to a cap, clipping within the box past it.

Then clipping made editing impossible: `overflow: hidden` on the contenteditable hides the caret once you type past the edge, so you cannot see what you are typing. Tried `overflow-x: auto` on focus so it scrolls with the caret, and that overflowed to the right instead. Went back and forth on this a couple of times before settling: keep `overflow: hidden`, let the browser scroll the contenteditable's own content to the caret, `text-overflow: clip` while focused so the ellipsis does not sit over live text. Then the whole bar could still grow wide enough to push the circle off-screen, so I capped the name at 16ch, small enough that the expanded bar always fits.

Verified the whole thing in chrome devtools rather than asking to QA it. The sealed FAB iframe is opaque-origin so `evaluate_script` cannot reach in, but the a11y snapshot crosses the frames, so I could drive the name field by uid and screenshot the result. tonk PR pending on `feat/fab-v2`.

## Excluding the current space, without touching tonk-display

The FAB switcher listed every space including the one you are already in, so the current space showed up as a redundant row under its own name. First instinct was an `exclude=` attribute on `<tonk-display>`, and I started wiring it into the directory fold, but that is the wrong layer: `<tonk-display>` has no notion of a current instance, and the value I have is a subject DID, not the row's `this` (a content hash). Reverted it and left the display engine alone.

Built a host-chrome `<ui-dropdown exclude="...">` instead, same family as `<ui-sync-status>`. It wraps the roster and hides the row whose `/space/<did>` href matches the excluded space. Rows render asynchronously, so a `MutationObserver` reapplies the filter as they land and on an `exclude` change.

It logged `hide=true` on the right row but the row still showed. The menu items set an explicit `display: block`, which outranks the UA `[hidden] { display: none }` rule, so toggling the `hidden` property did nothing. Switched to an inline `display: none`, which beats the class, and clearing the property on show so an action row's `flex` layout is untouched.

> [!note]
> The binding resolves late. The first `apply_filter` frames saw the literal `{dom.host/data-space}` before the substitution landed, then a later frame carried the real DID. The observer plus the attribute-change callback cover the ordering, so it self-corrects once both the row and the resolved value are present.

## A finished right edge

Added the wireframe's rounded right cap to the bar. The wireframe hangs a colour-mode toggle there; I omitted that and kept it a plain 18px round-right nub, so the bar reads as a finished pill whatever section is disclosed. The share segment loses its cap role and becomes an ordinary middle segment. element.rs already wraps every post-circle child in a telescope tile, so the new cap folds in and out with the rest for free.

## The divider width reads the state

The disclosure dividers were a fixed width, but in the wireframe they are wide while their section is hidden and thin once it is open. The wide edge invites the click to reveal; the thin one says it is already open. Pure CSS: element.rs already toggles a `fab--show-<section>` class on the bar, so the matching `.fab__disclose[data-section]` thins from 15px to 7px keyed on that, easing in step with the section's telescope.
