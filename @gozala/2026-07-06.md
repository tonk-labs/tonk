# July 6th

## Routing collapsed into two attributes

The four-element routing stack is gone. `<tonk-host>`, `<tonk-repository>` and `<tonk-branch>` existed only to catch bubbling consumer events and annotate them with a repo and branch, which is a document listener's job, not an element's. Now `tonk_host::install()` attaches the operation listeners to the document at boot, and routing context is a plain `with="branch@repo"` attribute resolved from the consumer's nearest ancestor at handle time. `<tonk-site>` is the only routing element left, and it grew a required `allow` attribute that declares what reach its sealed guest may request: `*`, or explicit locations. The portal bridge enforces it at two chokepoints with a typed denial, replacing the old `cross_repo` boolean that silently coerced an off-repo request into the pinned one. Grammar lives in a new `tonk-host/src/location.rs` with native tests; `meta@profile:tonk` names the profile endpoint, and there is deliberately no `self` token since an embedder that can write `with` can repeat the same location in `allow`.

The other half of the collapse: sealed guests no longer relay operation envelopes over `window.tonk`. The guest installs the same real host IO surface the top page runs, and the only thing that crosses the iframe boundary is HTTP, through the portal bootstrap's `window.fetch` override. `window.tonk` is sugar for apps, not the elements' transport. One trap on the way: `Request` objects absolutize paths against `baseURI` at construction, so guest fetches must go out as string paths or the override sees a cross-origin URL it cannot relay.

## connectedCallback on a detached element

Chased a "no tonk host installed" error across three transport architectures before instrumenting instead of guessing. The diagnostic that cracked it printed `connected=false root=div` from inside `connected_callback`: when a render pass appends and then removes a row inside an outer custom-element reaction, the spec queues the inner callbacks and delivers them after the outer reaction finishes, by which point the diff already detached the row again. `<ui-sync-status>` subscribed synchronously in that callback, so its subscribe event bubbled to a detached fragment root and died before reaching the document listeners. The fix defers the subscribe one microtask with an `is_connected` guard. Not proud of how long the guessing phase lasted; the one round of targeted logging did what five plausible fixes could not.

## Frames the consumers could not read

The disc still would not settle after the dispatch fix, and the second instrumented log found why: `status=None` on every frame. The host parsed each SSE frame with serde_json and re-serialized for the consumer with serde_wasm_bindgen, which turns a Rust map into a JS `Map`, whose entries `Reflect::get` cannot see. Every consumer reading conclusions by property access got structurally unreadable frames. The old bridge relay used `JSON.parse`, which is why this never bit before. The host now `JSON.parse`es the frame text directly: plain objects, one conversion fewer, and the wire contract restored.

## Navigation without reloads

Guest link clicks relayed to `handle_navigate`, which did `window.location.assign`, a full page reload per click. It now goes through the same `pushState` plus synthetic `popstate` the worker-initiated navigate uses, so the top `<tonk-site>` re-routes its `path` attribute in place. Also taught the sync drain to log its cause (the burst-opening request, with the heartbeat tagging its polls `?why=idle|visible|online`), made the SW stamp `sync:offline` from its own `offline` event instead of relying on a page poke that stops when offline, and hooked pause-sync to alt-click on the FAB cap, resurrecting the removed double-click machinery on the new `with=` routing. The dev hot-swap pill turned out to be blanketing the FAB's bottom-right dock with an invisible 128x48 hover zone eating drag pointerdowns; it is a 16px corner nub now.
