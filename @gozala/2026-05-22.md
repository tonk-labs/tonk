## Command Pallet

Reading through @jackddouglas notes and seeing snippets like this resurfaced an old idea which I think might become pretty relevant soon enough

```js
tonkLayout.emit('focus-next');
tonkLayout.emit('open-tile', { entity, view, model });
```

Specifically above looks very much like command execution. Majority of modern code editors and ancient ones have some form of command execution, and seeing above makes me want to suggest that there should be commands _(that I have being calling transient concepts)_, something like this

```yaml
command!:
	description: Focuses tile in the next column
	name: focus next
	context: board

command!:
	description: Open a new tile in the next column to the focused one
	name: open tile
	context: board
	# what input does command needs
	input: tile

# describes what qualifies as a tile that above command takes as input
rule!:
	description: Asserts tiles by finding entities that conform to given model & have a view
	assert: tile
	when:
		# model is a concept
		- assert: concept
			where:
				this: ?model
		# view is for that concept
		- assert: view
			where:
				this: ?view
				model: ?model
		# entity matches the model
		- assert: ?model
			where:
				this: ?entity		
```

Few interesting things to note in the above sketch:

- We can have our **⇧⌘P** command pallet in the interface

- Where you could perhaps type things like `focus next` and `open tile` and as you type we narrow down commands

- If command like `open tile` may require input like `tile` to do a thing

- We can have (deductive) rules that can provide completions

  > [!note]
  >
  > deductive rules are kind of like saved queries or "views" in relational databases

- Given such rule we can infer all possible and likely offer fuzzy search like thing

Sometimes we may need actual inputs though like when thing does not exist in a database e.g. what to name project, but we could potentially have a special model + view pair for it that renders text input field that user can type and submit

Maybe I am too developer minded, I do not know but I can't stop but feel that this is a the right design principal and action should be executable by a user and applications should not have a choice to not expose functionality. In addition if there is a command for everything dragging command from command pallet and sticking it into a view where it's relevant seems like great affordance to have. In addition if everything has a command that also means that agents can execute them without having to interact with user interface to do so.

## Effects

```yaml
concept!: &counter
  description: The most basic counter in the world
  with:
    count:
      the: xyz.tonk.counter/count
      description: Current count on this counter
      cardinality: one
      as: unsigned-integer

concept!: &increment
 	transient:
  description: Increments counter by given value
  with:
    counter:
      description: Counter being incremented
      the: xyz.tonk.increment/counter
      as: entity

concept!: &decrement
 	transient:
  description: Increments counter by given value
  with:
    counter:
      description: Counter being incremented
      the: xyz.tonk.decrement/counter
      as: entity

rule!:
  assert!: counter
  when:
    - assert: increment
      where:
        counter: ?this
    - assert: counter
      where:
        this: ?this
        count: ?c
    - assert: math/sum
      where:
        of: ?c
        with: 1
        is: ?count

rule!:
  assert!: counter
  when:
    - assert: decrement
      where:
        counter: ?this
    - assert: counter
      where:
        this: ?this
        count: ?c
    - assert: math/difference
      where:
        of: ?c
        subtract: 1
        is: ?count

counter!: &counter-demo
  count: 0

increment!:
  counter: counter-demo
```
