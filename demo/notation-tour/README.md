# The notation tour (demo)

A space whose home is a notebook that tours the Dialog notation: every
```` ```notation ```` block in it is a cell the space's worker reads, expands,
analyzes and compiles with `dialog-notation` (at the revision this branch
pins), runs against the space's branch, and answers with what each form did
and what each stage of the pipeline gave.

Everything here is demo scaffolding on a proof-of-concept branch.

## See it

```bash
.claude/skills/run-app/dev-web.sh      # serves the app on :8080; logs in /tmp/tonk-run/
```

(In this container a cold build took about 80 minutes at
`CARGO_BUILD_JOBS=2`; with nix, `nix develop -c dev:web` does the same.)

Open http://localhost:8080/ once and let the new profile finish its
onboarding, then open:

    http://localhost:8080/seed/http://localhost:8080/library/notation-tour.yaml

name the space (say "Notation tour") and create it. The space opens on the
tour notebook. Press Run on each cell from the top (each cell reads the
definitions of the cells above it, and the facts the cells above wrote).
Under the Views cell, press Watch live before running the cells below it:
the to-dos they add arrive in the watched card as the driver's patches.

To run the whole tour headless and check every cell:

```bash
cd demo/notation-tour
ln -sf "$(npm root -g)" node_modules
node tour.mjs                          # screenshots in ./shots/
```

To run every cell without a browser (the cell evaluator over an in-memory
branch):

```bash
cargo test -p tonk-analyzer --test notation_tour
```

## Where it lives

| piece | file |
|---|---|
| the tour, as Markdown | `demo/notation-tour/tour.md` |
| the seed a space is created from, generated | `rust/tonk-core/assets/library/notation-tour.yaml` (`python3 demo/notation-tour/build.py`) |
| a cell, in the notebook | `rust/tonk-inspector/src/notation_cell.rs` (two hooks in `notebook.rs`) |
| the body's content type through the host | `rust/tonk-host/src/{consumer,ops}.rs` (`evaluate_as`, `contentType`) |
| the worker side, on the existing `/evaluate` route | `rust/tonk-worker/src/router/notation_tour.rs` (`evaluate_route` in `evaluate.rs`) |
| the live view, on the existing `/query` route | `notation_tour.rs` (`live_frames`, one branch in `query.rs`) and `notation_cell.rs` (`apply_patch`) |
| the evaluator | `rust/tonk-analyzer/src/notation/tour.rs` |
| every cell runs | `rust/tonk-analyzer/tests/notation_tour.rs` |
| the browser proof | `demo/notation-tour/tour.mjs` |

## What is real and what is scaffolding

Real: the notation's own pipeline (`dialog-notation` at the pinned
revision: `parse_document`, `check_forms`, the analyzed kernel trees,
`compile`'s steps), its writes committed to the space's branch through the
branch's stack like any commit, its queries answered by Dialog's engine,
its views rendered and watched by the notation's driver.

Scaffolding: the cell UI and its JSON answer, the seed generated by
concatenation, keeping each run form as `syntax.form/is` (the notation
does not write syntax itself; Dialog's tests do it the same way), the
250 ms poll of a live view, and the content-type branch on `/evaluate`.

## Known limits

- Definitions live in the analyzer's memory only, so a cell re-reads the
  cells above it each time. Nothing about a concept is stored by the
  notation; the tour's concepts are not tonk concepts.
- A live view's rules stay laid on the branch's session overlay after the
  page lets go (`Live::lay`); the stream ends, the rules do not.
- `total: (+ ?p : ?q)` in the head of a multi-premise select answered a
  cross product here (each pair with every total); the tour leaves it out.
- A check written as a rule can only warn, over the expander's few
  built-in premises.
