# Browser and in-agent screen coverage

The reference is the generated Gooey prototype at `a7a9c88`. It includes the change that sends a passlink directly to the space and keeps template selection as an exploration. [Prototype index and change log](https://github.com/tonk-labs/gooey/tree/a7a9c88/prototypes)

| Surface | Implementation and remaining differences |
| --- | --- |
| Empty hub and troubleshooting | The starter appears once the browser knows it is signed out and has no spaces. The six questions open independently, Escape closes the current question, and local creation remains reachable. Signed-in browsers with no spaces keep the spaces sheet. Gooey lists this as an open design question. |
| Account lookup and sign-in | Pausing, blur and Enter resolve an address. A known account offers its passkey. A new account asks for a display name. Retyping the email invalidates the previous answer and preserves the draft name. The standalone wordmark returns to the hub. Contextual tasks keep a visible cancel action. |
| Account success and confirmation | Activated accounts return to the hub or interrupted destination. The worker requires confirmation before a second device can hydrate an unactivated account, so this flow still offers resend and waits for activation. The prototype's immediate new-account receipt and optional browser-space selection differ from the current registration and custody behavior. The current worker hands over the signed-out workspace's holdings together. |
| Recovery and adding a replacement passkey | The two open recovery PRs own enrollment, phrase verification and replacement-device work. The new account sheet still needs integration with those changes. [Recovery implementation](https://github.com/tonk-labs/tonk/pull/1341) · [Recovery dialog](https://github.com/tonk-labs/tonk/pull/1347) |
| Populated hub, space rows and account sheet | The existing hub provides loading, failure, sync indicators, account management, inline creation and receipts. Rename, duplicate and the leave/delete question now appear under the expanded space. Removal retains ownership-specific consequences. The directory projection lacks the mock's per-row member count and role. The phone hub uses its header and inline create form. Nested settings keep the return bar. Undo remains limited to supported operations. |
| New link and existing links | The issuer’s space grant determines the available roles. A passlink carries its role and optional deadline through redemption. The picker reads the space’s routes and directory views. A view address opens that destination using existing access. Gooey’s separately listed, revocable short view URLs and recovery of earlier tabs’ bearer URLs remain open. |
| Connect, choose access, progress, connected and refused | Agent approval uses the task sheet, verb-led progress and the worker's actual phases. Selecting a reused agent and choosing the access of each space remain available. Expiry, grant failure and cancellation use the service result; displaying these states requires an actual request. |
| Device link, terminal space link, remote Tonk sign-in and custody consent | Device-link approval uses the task-page system. Remote sign-in and custody now share its field and button styles. Custody can occupy the originating guest's seat or open as a native modal. The cross-Tonk and anchored custody arrangements are adaptations for existing product flows. |
| Activation, join, private and error walls | The merged stack implements activation, refusal, expiry, the bare join form, private and signed-out walls, missing pages and failed startup. Emailed invitations now share the same task sheet across signed-out, wrong-account, unconfirmed, joinable, incomplete and gone states. The space owns its own content after entry. |
| In-agent cards | The hosted ask, tell, receipt and view frame use the handoff stylesheet and five font files. The host owns the surrounding chat chrome. The signed-in agent still asks the person to choose access before accepting a passlink. The one-chat guest, matching-code browser lending, chat-branch pending counts, save-to-main, offline write queue and complete change attribution require host, identity or sync behavior beyond the card stylesheet. |
| Settings and design explorations | The account sheet includes profile details, passkeys, connections and destructive confirmations. Cross-tab account switching and changing a connection's per-space role remain open in Gooey. The blank-space template gallery and sample space data are prototype explorations. |

The comparison should distinguish a deployed route, an isolated browser test, and a state inspected only in source. The stylesheet match establishes common design values. Individual screenshots and interaction checks establish what actually rendered.
