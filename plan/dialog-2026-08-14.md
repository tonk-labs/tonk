# Dialog upgrade: tonk-2026-08-14

Bump the dialog-db pin from `e8bbe462` (the `perf/read-concurrency` side branch, which diverged
from dialog main around 2026-07-09) to the `tonk-2026-08-14` tag
(`176a6046fb40ab3586e87a4464a6de1326aea43e`, dialog main), adapt tonk to the API changes, and
retire local implementations of things dialog now does natively.

**Status.** Done. [tonk#703](https://github.com/tonk-labs/tonk/pull/703) is open against
`staging` with every CI check green (lints, both CLI builds, e2e, and all four native/web
test legs). The pin is `tonk-2026-08-15` — the `tonk-2026-08-14` tree plus
[dialog-db#445](https://github.com/dialog-db/dialog-db/pull/445), a retain bug this migration
surfaced (see "Dialog bug found" below), merged upstream and tagged.

Stage 7's live verification is `rust/tonk-cli/tests/live_migration.rs`: a spot on real
storage where the library seeds, a native rule installs and fires through commit-time
induction, and the command that triggered it is swept. It fails if the rule install is
removed, so it pins the behavior rather than just exercising it.

## Dialog bug found

An operator's `Retain` published against the head its build-time handle cached and never
refreshed it. The access branch IS the profile repository's `main`, so any other write to that
repo advances the same head through a different handle, after which every delegation save fails
with `Version mismatch` permanently. Symptom here: three `tonk-worker` account-state tests
failed the moment the pin moved. Fixed upstream by refreshing before the retain (and after a
lost race), with a regression test that reproduces it without concurrency. Merged as
`f0449ce2` and tagged `tonk-2026-08-15`, which is what this branch pins.

## What CI caught that a native run cannot

Two failures only the wasm leg can produce, both worth remembering:

- `ArtifactView` field access in a `#[cfg(target_arch = "wasm32")]`-only branch of
  `router/repository.rs`. The native build never compiles that code, so the migration's
  accessor change looked complete until the wasm target was built.
- `tonk-evaluator`'s whole test suite failing with "failed to find or execute Node.js". The
  crate-global `wasm_bindgen_test_configure!(run_in_browser)` lived in `effect_query.rs`,
  which this migration deleted; without it the web leg runs under Node, which cannot serve
  the storage APIs these tests need. Restored in `evaluate.rs`.

The lesson is the one already in the notes: after deleting a module, check whether it carried
a crate-global test directive, and always build `--target wasm32-unknown-unknown --all-targets`
before pushing.

Three more surfaced only in CI, each worth knowing:

- `router::tests::it_walks_to_a_leaf_and_decodes_an_entry_key` asserted the OLD key layout's
  flat `entity` / `value-type` fields. The M3 format is variable-length, so `tree/key` returns
  a decoded `parts` list instead. Only the web leg runs this test, so the stale assertion
  survived the format change unnoticed.
- `router::transfer::tests::it_roundtrips_export_then_import` compared a source export against
  a destination one. `dialog.db/revision` records carry the minting repo's issuer and edition,
  so they cannot match — the same reason founder membership rows were already excluded.
- `session::tests::it_bounds_the_session_within_the_ttl` named its scratch profile from a
  per-PROCESS counter, but the runner starts a process per test, so two concurrent tests
  collided on one profile directory and one lost the writer lock. Dialog's `unique_name`
  folds in the pid for exactly this reason; the test uses it now.

And one genuine race in the e2e suite, fixed rather than retried around: `wait_for_text_containing`
retried its `find` but propagated a failed text read, so a list re-rendering between the two
aborted the wait with "stale element reference" — the very race the wait exists to absorb.

## What changed in dialog since our pin

Everything on our side branch (subscription overlays, DRed maintenance, columnar-key perf work,
proof memoization, cloneable Storage) landed on main as proper PRs, so nothing we rely on is
lost by moving to main. On top of that, main carries:

1. **tonk-2026-07-22 format redesign**: columnar search-tree nodes, version control with a
   history index, new `Revision` shape (`edition` + `context`), and a reserved `dialog.`
   attribute namespace: the write path rejects asserts to `dialog.*`, so every tonk-owned
   attribute moves to `db.*`. Also `Origin` → `Replica` renames in dialog-injected facts.
   The unmerged PR #635 (`feat/dialog-vcs`) absorbed exactly this range and is our base.
2. **Native deductive rules with aggregation** (#416): a `reduce` clause beside `when`/`unless`;
   grouping is derived from non-reduced head fields.
3. **Native inductive rules** (#420): commit-time trigger-indexed dispatch, rules stored as
   content-addressed `dialog.rule/*` facts, installed/uninstalled by plain
   `tx.assert(rule)` / `tx.retract(rule)`; `dialog.concept/transient` marks command concepts and
   `Transaction::dispatch` stages transient facts that trigger rules but never persist.
   The `RuleSource` / `with_rules` seam tonk used (dialog PR #364) is **gone**, so this
   migration is forced, not optional.
4. **Tree inspection through queries** (#428): seven `tree/*` resolvers (`node`, `span`, `key`,
   `entry`, `value`, `blob`, `manifest`) run through the ordinary planner/evaluator, replacing
   tonk's local tree traversal.
5. **Delegations as synced data** (#436–#440) and **login by pulling the account** (#442):
   delegations are `dialog.ucan/*` facts + envelope blobs on a synced access branch; a
   tree-backed prover replaces the certificate file store; session grants are in-memory; new
   bottom crate `dialog-identity` (holds `Profile`/`Authority`); `pull().download()`
   materializes a branch up front. Operator public API is mostly unchanged, but auth
   storage/hydration paths are not.
6. **Typed authorization errors** (#422/#423, serde-tagged): `AuthorizeError` and
   `Rejection` travel intact from the S3 boundary to the caller and serialize with a
   `kind` tag.
7. **Ordered relations** (#429): new capability, nothing to port.

## Stages

1. **Base on PR #635.** Merge `origin/feat/dialog-vcs` into `feat/dialog-08-14`
   (12 conflicted files, mostly `tonk-cli`, `tonk-fab`, `tonk-schema/replica.rs`,
   `tonk-workspace/ui_sync_status.rs`, plus the two Cargo files that get rewritten in stage 2
   anyway). This inherits the `db.*` rename across Rust + library YAML, the Replica renames,
   the Revision/sync rework, and the M3-format tree-inspector port.
2. **Bump the pin** to `176a6046…` for every `dialog-*` entry in the workspace `Cargo.toml`;
   add `dialog-identity` if anything needs it directly. `cargo check` the workspace natively,
   fix breakage crate by crate.
3. **Rules migration.** Replace tonk's stored-rule machinery with native rules: stored
   deductive rules (tonk-schema `deductive_rule.rs` / `rule.rs` / `rule_query.rs` and the
   evaluator's `with_rules` injection) become `tx.assert(DeductiveRule)`; the command/effect
   path moves onto `dialog.concept/transient` + `Transaction::dispatch` where it is a drop-in,
   keeping tonk's `Provider<C>` capability gate for effects that run tonk-side code.
   (Refined by the codebase survey; see "Local implementations" below.)
4. **Tree inspector.** Point the inspector's data path at the `tree/*` resolvers via ordinary
   dialog queries; delete the local traversal port (dialog-reactor `formula.rs` and the worker
   endpoint that intercepts `tree/*`).
5. **Typed error mapping.** Per the 08-13 journal notes: the access service emits
   `AuthorizeError`/`Rejection` directly instead of `ErrorCode` (its variants map nearly
   one-to-one); delete `ErrorCode` and the client's `classify_response`; collapse the three
   stringly classifiers (`classify_pull` in `tonk-worker/src/router/join.rs`,
   `classified_service_failure` in `router/sync.rs`, `failure_from_code` in
   `tonk-workspace/src/sync.rs`) into plain matches on the typed variants —
   `"CREDENTIAL_REVOKED"` appears as a bare literal 16 times across 4 files today. Both
   sides live in this repo and ship together in this PR. Tonk code that converts a dialog
   error must map variants, not `to_string()` them.
6. **Green.** `cargo fmt --all`, `cargo clippy --all --all-targets --all-features -- -D warnings`,
   native test suites, wasm `--no-run` compile of the workspace (memory: wasm-gated tests skip
   the native build), browser test leg as CI allows.
7. **Live verification.** Fresh local instance: CORE seeds, `blank:`/`space:`/`concept:`
   resolve, pull/push, spaces render (the #635 checklist), plus a stored-rule and a command
   round-trip through the native dispatch path.
8. **PR against `staging`**, superseding #635 (note it in the description).

## Local implementations to retire or rewire

From the codebase survey (≈3,400 prod lines retireable, ~1,800 test lines with them):

**Delete outright**

- `dialog-reactor/src/formula.rs` (754 lines): the hand-rolled `tree/node|child|entry|key`
  inspector that bypasses the planner and pokes `dialog_search_tree` internals. Replaced by
  the seven `tree/*` resolvers. Also delete the interception arm in
  `tonk-worker/src/router/query.rs:121-140` and the `Query::formula()` wire escape hatch in
  `tonk-schema/src/query.rs` — with resolvers in the planner, tree queries become
  subscribable for free (today they explicitly are not).
- `tonk-evaluator/src/effects.rs` (724 prod lines): tonk's semi-naive fixpoint
  (`MAX_ROUNDS = 16`), replaced by #420's commit-time dispatch.
- `tonk-evaluator/src/effect_query.rs` (256 lines): effect lookup + the V1
  "must trigger on a transient" validation, a restriction that compensated for the local
  fixpoint; check nothing depends on it before dropping.
- `tonk-schema/src/rule.rs` (395 lines): inductive-rule packaging into `db.effect/*`,
  including the async `Retracting` machinery that re-reads stored JSON bytes to make
  retraction hit — dialog's content-addressed `dialog.rule/*` facts make
  `tx.retract(rule)` exact.
- `tonk-core/src/effect.rs` (336 lines): the `db.effect/on` reverse index existed solely to
  serve the local fixpoint; `Effect`/`Polarity` may survive briefly as analyzer IR.
- `tonk-schema/src/deductive_rule.rs` (319 lines): already dialog-native in shape
  (`db.rule/{source,conclusion}` are dialog's own names at the old pin); at the new tag
  `DeductiveRule` implements `Statement` directly, so this collapses into `tx.assert(rule)`.
- `tonk-schema/src/rule_query.rs` (276 lines): enumerating installed rules becomes an
  ordinary query over `dialog.rule/*` facts (verify the tag exposes them queryably).
- `tonk-core/src/claim.rs` transient wrapper (`ConceptDescriptor::Durable|Transient`):
  its own comment marks it a fork pending upstream design; #420 settles the design.
- `tonk-tree/src/key.rs` byte-layout decoding (~120 of 221 lines): a second, client-side
  copy of dialog's key encoding; consume the `tree/key` resolver instead, keep the
  `Part`/`Component` coloring.
- Trigger detection in `dialog-reactor/src/command.rs` (`decode_concept`,
  `trigger_attributes`, `by_attribute`, `match_transients`; ~200 lines): this IS #420's
  trigger index. The synthetic-`Match` decode bridge dissolves if `Transaction::dispatch`
  hands the trigger's facts to the handler.

**Keep**

- `dialog-reactor` subscriptions, branch/handle caching, commit CAS/transactor-lock path,
  SSE plumbing (~1,900 lines) — orthogonal.
- The `Provider<C>` compile-time capability gate and `TypedCommand` in
  `dialog-reactor/src/command.rs` (~180 lines) — no dialog equivalent; effects that run
  arbitrary async Rust (repo creation, key gen, network IO) stay tonk-side, post-commit.
- `tonk-schema/src/command.rs` (499 lines) — pure app schema; its doc comments record
  decode-path landmines (older seeded descriptors, the `remote`-as-`Value` trap) to
  re-verify against native dispatch.
- `tonk-tree` UI (`web.rs`/`inspector.rs`/`dom.rs`, ~1,150 lines) — repoint `model.rs`
  (a JSON contract, no dialog deps) at the `tree/*` resolvers.
- `router/command.rs` dispatch concurrency + `run_scheduled_polls` drain.

**Corrections to the stages above**

1. Tonk never used the `RuleSource`/`with_rules` seam (two stale doc comments only), and its
   deductive-rule storage already matches dialog's shape — stage 3's deductive half is a
   collapse, not a forced rewrite. The inductive half (`db.effect/*` + local fixpoint → native
   `dialog.rule/*` + commit dispatch) is the real migration.
2. #416 aggregation, like #429 ordering, is pure new capability — nothing to port.
3. The `TODO(stm)` isolation bug (`tonk-worker/src/router/command.rs:161-166`: commands read
   durable state, decide, and commit with no isolation) may be fixed for free if handlers run
   inside `Transaction::dispatch` — confirm during stage 3; it is a correctness argument for
   this migration, not just a line-count one.

## Risks

- **Storage format**: the 07-22 redesign changed the binary format; existing local repos
  predating it will not open. #635 verified against a fresh instance; same stance here.
- **Auth path churn** (#440/#442) lands on `tonk-account`, `tonk-cli`, `tonk-worker` auth code;
  the prover now reads the access branch on demand, and any tonk code that assumed an eager
  hydration pass needs the `pull().download()` form instead.
- **FAB regression** #635 left open; its later commits carry a candidate fix
  (`40735733 fix(fab): resolve the space name/status when the routing context lands late`) —
  verify live in stage 6.
- Merge is behind by 58 staging commits: roster/passkey/account work landed since; the
  conflict resolution must keep staging's behavior and only take #635's dialog adaptations.
