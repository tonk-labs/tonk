## Niri Layout
Now that the basic structure of `<tonk-layout>` is in, I'm experimenting with implementing [[Irakli Gozalishvili]]'s [tonk/rust/tonk-layout/prototype-pull.html at 204934656e5efc31b2e2ad9338c11a56d6964472 · tonk-labs/tonk · GitHub](https://github.com/tonk-labs/tonk/blob/204934656e5efc31b2e2ad9338c11a56d6964472/rust/tonk-layout/prototype-pull.html) pull prototype for the niri mode.

I need to make a couple changes to the effects. `open-tile` will echo back the newly minted tile ID so the WM can respond accordingly and reconcile it properly. I'm also creating a new `tonk-layout:opened` outbound event that fires when `open-tile`'s `/evaluate` POST resolves successfully.

The niri view will listen for `opened` and write a `niri-placement` row for the tile URI it receives, or a `niri-column` row if a new column is created along with the new tile.

## Linear
Added a few concepts to map Linear-style work:
- `workspace` for the team workspace
- `project` for specific projects in the workspace; includes:
	- title
	- description
	- status
- `issue` for an issue in a project; includes:
	- title
	- description
	- status

Two new `view`s: `projects` and `issues`.

Found a few bugs along the way that should be addressed in follow ups:
- [ ] `slide views` doesn't list `<tonk-display>` views
	- The command is claim-driven on `text/html` assertions, not by the `view` concept
	- It needs to be taught about the new concept shape for views that can be rendered in `<tonk-display>`
- [ ] `slide invite` doesn't carry the remote
	- `slide share [concept|view]` includes a remote at the end of the URL if configured
	- `invite` subcommand only mints UCAN chain, no remote endpoint
- [ ] `<tonk-display>` doesn't propagate it's `space` and `branch` into nested `<tonk-concept>`s
	- `<tonk-concept>` without explicit `space`/`branch` falls back to relative `/query` that returns notching in main-shell DOM
	- Need better way to pass/infer, esp in nested components
- [ ] Stable identifiers for entities
	- `view` rows content-addressed from body so editing mints a new entity
	- Stale rows need to be retracted by explicit entity URI every edit
