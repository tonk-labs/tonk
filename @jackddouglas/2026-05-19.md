## IFrames
`fetch` will be replaced with `postMessage` so we can drop the SW path rewrite and iframe can lose `allow-same-origin`.

Goals:
- Iframe-side JS reads branch data only through `tonk.subscriptions.<name>` where `<name>` was declared up-front in the view's manifest
- Tooling can query which views read a given attribute or need a URL entity via single exact-attribute [[Dialog DB]] selection
- No more `fetch`
- Prioritize reading; defer effects, parameterization, and reactor deltas for now

Views must declare subscriptions up-front in a manifest claim in Dialog. This makes them queryable and preserves a strong mapping between views and underlying data.

Later, effects could also be declared up front and fired by name in the iframe.

Manifest which declares subscriptions will live as a sibling claim on the view entity, `dialog.view/manifest` alongside `text/html` body.

A reactive signals API will be included in the injected library.

A view is an entity carrying two sibling claims:
- `text/html` body with HTML/CSS/JS
- One `dialog.view.subscription/<name>` claim per subscription
	- Claim's value is JSON-serialized `ConceptQuery`
	- Bridge reads these to subscribe, tooling reads them to render full query body when asked
- Index claims emitted for tooling queryablility
	- `dialog.view/reads` and `dialog.view/needs`
	- Bridge ignores these, they exist so tooling can query structurally without parsing `ConceptQuery` blobs

Lifecycle when shell mounts an iframe at `/api/repository/{repo}/branch/{branch}/host/{host}/{entity`:
1. SW serves body wrapped in shim that loads bridge module
	1. Registers `ViewBinding { repo, branch, manifest }` against iframe's client ID
	2. Replaces `GuestBinding` we have now
3. On load, iframe-side bridge posts `hello` over `MessagePort` to `navigator.serviceWorker.controller`
4. SW looks up `ViewBinding`, opens each declared subscription against reactor, and sends initial snapshots + subsequent updates as `data` messages
5. Iframe-side JS fires effects by name, SW substitutes `$args.*` into declared YAML fragment and runs it through existing `/evaluate` pipeline

I want to land all of this incrementally so Gavin can get unblocked earlier. I'll start with read-only `postMessage` bridge, then add effects and richer parameterization, formalize in `tonk-schema`, and possibly propose `$name` into `tonk-notation` for substitutions in effects.

First version of manifest schema:
```yaml
subscriptions:
  people:
    terms:
      this: { ?: { name: this } }
      name: { ?: { name: name } }
    predicate:
      with:
        name: { the: "person/name", as: Text, cardinality: one }

  current:
    terms:
      this: "$entity"
      name: { ?: { name: name } }
    predicate:
      with:
        name: { the: "person/name", as: Text, cardinality: one }
```

SW -> iframe data envelope:
```json
{ "v": 1, "type": "data", "name": "people", "rows": [ {"this": "...", "name": "Alice"}, ... ] }
```
